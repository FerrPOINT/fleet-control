# Анализ требований

Отделить бизнес-факты PM от допущений. Изучить все разрешённые материалы и
комментарии. Для каждого требования дать стабильный ref/revision, источник,
actor, наблюдаемое поведение и acceptance criterion. Зафиксировать scope/non-goals.
Добавить negative/boundary, permissions/tenant, retry, versioning и partial-failure
cases. Отсутствующий факт — один конкретный вопрос, не предположение о продукте.
Не выбирать архитектуру и не выполнять разработку. Итоговая coverage matrix
связывает требования с criteria, источниками и будущими проверками.
