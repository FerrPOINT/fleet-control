## Injection Boundary

No production hook is required. The QA binary changes only its private
`ContainerControlConfig.python` to `/compiled/cut-transport`, installed from
sealed QA sources. It still passes Fleet's exact `-I -c BOOTSTRAP /base-runtime`
arguments and four captured modules to the actual Python utility process.
The wrapper checks all those bytes before delegation; it neither manufactures
a response nor implements replacement planning or native custody.

1. Real Fleet provisions/starts two real Hermes namespaces, proves their mount
   subpaths/identity and completes genuine chats against the controlled model.
   It arms the cut with the actual original generation, stop ID, container ID,
   registration/snapshot hashes, then requests revision A while a genuine run
   is active. Drain and unchanged files/generation are asserted before release.
2. At `StoppingPrevious`, the wrapper exclusively fsyncs its QA-only one-attempt
   latch BEFORE delegating the exact original stop. It validates the real Base
   exit0 ACK and original physical `namespace_exited` receipt, reads the actual
   private stop journal, fsyncs redacted ACK/hash/file-identity evidence, and
   withholds stdout. No Base permit, receipt, journal or DB phase is synthesized.
3. The Rust driver reads the public repository and asserts `StoppingPrevious`,
   no previous-stop/candidate/rollback/readiness phase receipts, unchanged
   immutable private plan, original physical exit, drain and peer isolation.
   Host QA restarts the SAME controller CID/image with a new physical start
   timestamp inside the wrapper's 55-second withholding window (and before the
   unchanged 60-second transport deadline). Gate-to-ready
   wait is bounded to ten seconds; timeout/failure cannot become acceptance.
4. After restart, the real supervisor must recover its original anchor and
   current lease. Replaying the original stop is refused by the durable QA
   latch. Progress therefore requires the actual Base4 `read_original_stop`
   response, the immutable claim/plan and existing native lease/phase guards.
5. Recovered A must reach real readiness/effective publication. A next activation
   produces effective child B using F6 lineage. A further C uses the unchanged
   `QA_READINESS_DELAY_18` proxy (120 seconds against the product's 60-second
   readiness deadline), and must roll back to exact CURRENT B bytes/revision on
   its reserved NEW rollback generation. Original/candidate/predecessor exits,
   current native health, readiness hashes and actual applied heartbeat are
   checked. Genuine chats verify A, B, and B after rollback.
6. Peer launch, PID/start, physical mounts/specifications, managed files, native
   POST inventory and ACK-loss inventory remain identical across the sequence.
   Ordinary terminal stop must physically exit both published agents.

Only a fixture user is inserted through SQL, as in the original driver. The
additional SQL is a read-only authority-count query; all activation, recovery,
lease, run, receipt and custody mutations go through actual repository/runtime
methods and Base. Private saved config stays in the disposable controller volume.
ACK tracing stores hashes/IDs/receipts, not credential-bearing process commands.

## Reviewed Crash-Cut Boundaries

Successor to frozen `bc0b85ee47ceb159daf304b25665d1e1cb70a689` closes two
QA orchestration gaps; it does not rewrite that packet or its source seal.

The wrapper records its real PID/start ticks, Linux boot ID, original call ID,
ACK hash and absolute Linux monotonic 55s deadline in a private 0600 witness.
Publication time is charged to that same window. The host probes the actual
live owned process through the original controller. Host and container clocks
are NOT compared directly: the host anchors a conservative deadline BEFORE
the probe request, subtracts the whole round trip and a two-second margin,
and never extends that deadline. Both inventory CLI calls, original controller
epoch inspection, fresh probe immediately before restart, Compose restart,
post-restart inspection and inventory are bounded by the remaining budget,
with checks after each return. A late command which ignores its timeout also
fails closed. Missing/dead/foreign-epoch wrapper, expired window or controller
start drift cannot authorize the restart; a slow restart cannot produce host
success. Timeout does not imply cancellation of daemon-side effects: original
owned cleanup still runs and no cut acceptance/recovery stage is published.

Only cut-owned completion files use `cut_files.atomic_json`. It exclusively
claims one attempt, writes a unique no-follow 0600 tempfile, flushes/fsyncs all
bytes, atomically hard-links to a previously absent final name, unlinks its
tempfile and fsyncs the directory. There is NO replace/rename-over-existing
fallback. Existing final/symlink, deletion/retry, unknown fsync or link failures
remain failed attempts. Ready publication checks original private arm/attempt,
known stop ACK and live wrapper epoch; final JSON visibility cannot precede its
complete bytes. A malformed COMPLETED receipt remains a strict failure, not a
retry-until-parse loop. The original nine-scenario `put` is byte-unchanged.

## Unknown Effects

Unknown/malformed/nonzero stop response, absent/corrupt/private journal or lost
arm cannot produce the cut gate. The one-attempt latch prohibits a second native
stop even when the first acceptance is unknown. Missing original start/stop
proof, unknown preparation/start, absent immutable plan, foreign custody, wrong
generation or expired/unapplied/latest-epoch lease must remain held under the
unchanged producer guards. This supplement exercises ONE known cut; it does not
claim native execution of every held/unknown cut or process-only takeover.
